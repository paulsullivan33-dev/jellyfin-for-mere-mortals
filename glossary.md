# Glossary

The terms, collected. Each is explained at
first use in its chapter; this is the
one-place index.

**Access token** — the reusable credential
a client receives when you sign in, and
presents instead of your password on later
requests (chapter 6's lab drove the whole
server with one).

**Administrator** — an account that can
change server settings, manage libraries,
and create users. Everyone else is an
ordinary account, whatever their seniority
in the household.

**Client** — whatever plays the media: the
built-in web client, an official app, a
third-party player. The client declares
what it can decode; the server believes it.

**Collection type** — a library's declared
kind (movies, tvshows, music, and others),
which selects the rules its files are
scanned by.

**Container** — the wrapper a media file
comes in (MP4, MKV, FLAC). Not the video
inside it: a container is the envelope,
the codec is the letter.

**Codec** — the actual encoding of a video
or audio stream (H.264, HEVC, AAC, FLAC).
Whether a client can play a file is a
codec question first and a container
question second.

**Device profile** — a client's statement
of what it can direct-play: containers,
codecs, maximum bitrate and size. The
server's playback decisions are made
against it.

**Direct play** — playback where the file
is sent exactly as stored. The cheapest
outcome, and the one to arrange for.

**Direct stream** — playback where the
streams are copied but the container is
changed on the fly. Nearly as cheap as
direct play; part of the "remux" family
in chapter 7.

**Hardware transcoding** — re-encoding
done by a GPU or media engine (Quick Sync,
NVENC, VAAPI and friends) instead of the
CPU. Documented-only in this guide.

**Library** — a folder plus a declared
type. The unit of scanning, of browsing,
and of per-user access.

**Metadata provider** — an outside
database (TheMovieDb, TheTVDB, and others)
the server consults to identify items and
fetch posters, synopses, and cast.

**Policy** — the per-user settings object:
enabled libraries, playback permissions,
parental controls. The fence of chapter 6.

**Probing** — the server's own measurement
of a media file: codec, dimensions,
bitrate, duration. Local, factual, and the
basis of every playback decision.

**Remux** — repackaging streams into a
different container without re-encoding
them. See direct stream.

**Scan** — the library pass that discovers
files, probes them, creates items, and —
in later phases — links and decorates
them. A second scan cancels the first.

**Transcoding** — decoding and re-encoding
media live so a client can play it. Done
per stream, at a cost set by your
hardware.

**Trickplay** — the thumbnail strip a
client shows while scrubbing through a
video; generated by the server as a
background task, stored as server data.

**Virtual folder** — the API's name for a
library: a folder made virtual, with a
type and options attached.
